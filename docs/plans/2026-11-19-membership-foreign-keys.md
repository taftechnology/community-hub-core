# Membership foreign keys Implementation Plan

Slug: membership-foreign-keys
Status: approved (2026-11-19, Adnan Bin Hossen)

> **For agentic workers:** use superpowers:subagent-driven-development, test-driven-development inside each task, and verification-before-completion before reporting. One task = one commit. Reports go to `.superpowers/sdd/task-N-report.md`, never `docs/plans/` and never a commit.

**Goal:** the database refuses a role grant or user link for a user who is not a member of that organisation, checks the rows already there when the keys are added, and refuses to remove a membership that a grant or link still uses. Nothing a user sees changes.

**Architecture:** one contract migration (`0020`, three foreign keys, generated by drizzle-kit, with ` NOT VALID` added by hand to each statement per spec amendment A1), three `foreignKey(...)` entries in the access schema, fixture fixes, and new tests. - `packages/db/drizzle/0020_<generated>.sql`, `meta/0020_snapshot.json`, `meta/_journal.json`: generated. `packages/db/tsconfig.test.json`: one `include` entry for the new migration test.
