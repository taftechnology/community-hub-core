# Groups Implementation Plan

Slug: groups
Status: approved (2026-10-29, Adnan Bin Hossen)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A community can keep groups and ministries, put people in them with a `leader` or `member` role, read a group's leaders as a fact, and export a roster as CSV. Minors can be members, appear in no name list by default, and appear in an export only for a restricted reader through an audited read. The tables are `app.groups` and `app.group_members`, both with forced row level security. No route and no UI.

**Architecture:** A new `modules/features/groups` package (`@community-hub/groups`) has people's shape: `domain/` (errors, name normalisation, CSV writer), `db/schema.ts` (`groupsTables(app, { persons })`), `infrastructure/` (groups, members, export), and `public/index.ts`. `modules/core/people` gains one public function, `readRosterNames`, the only way groups reaches `app.persons`. `packages/db` keeps the single journal and gains migration `0014`.
