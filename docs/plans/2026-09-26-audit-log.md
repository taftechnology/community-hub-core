# Plan: audit log

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Append-only, hash-chained `app.audit_events` rows that verify from integer microseconds, including the first row of an empty organisation.

**Architecture:** Kernel owns action and purpose names only. `@community-hub/db` owns the table, the `BEFORE INSERT` trigger, the TypeScript encoder, `appendAuditEvent`, and `verifyAuditChain`. The trigger fills every chain field with `CASE WHEN` so a null previous row still writes seq 1. Verify reads microseconds as text and hashes with `bigint`, never a `Date`.

**Tech Stack:** TypeScript 5.8, Vitest 3, Drizzle 0.45.2, postgres.js 3.4.9, Postgres 17 (built-in `sha256(bytea)`), existing Docker Compose + PgBouncer.

**Spec:** `docs/specs/2026-09-25-audit-log.md` (approved 2026-09-26, Abdus Salam)

Status: approved (2026-09-26, Abdus Salam)

**Branch:** `feat/2026-09-25-audit-log` · one PR · 7 tasks, one commit each

## Global Constraints

- Hash version byte is `0x01`. Field order and the frozen digest are copied from the spec. Both the SQL function and the TypeScript encoder must equal `7a29119e629b70f9d9ff4ef69ebc874303ee4315a745f306cbddb802c129b5ad`.
- `occurred_at` enters the hash as `trunc(extract(epoch from occurred_at) * 1000000)::bigint`. The encoder takes a `bigint`. It does not accept a `Date`. Do not truncate the trigger to milliseconds.
- Genesis `seq` and `prev_hash` use `CASE WHEN prev IS NULL`. Do not write `IF prev IS NOT NULL AND prev.hash <> NEW.hash`.
- No `idempotency_key`. Two appends are two rows.
- `actor_id` is null only when `actor_kind` is `system`.
- `target_ids` rejects a null element and a second dimension.
- Retry only `SQLSTATE` `23505` on constraint `audit_events_org_id_seq_unique`, at most five attempts, inside a savepoint. Refuse any isolation other than `read committed`. Do not `SET TRANSACTION` after `set_config`.
- No `pgcrypto`. No bootstrap change. No S3, jobs worker, HTTP route, or `modules/core/audit`.
- No product `defineAuditAction` / `defineAuditPurpose` in `src`. Tests register the names they append.
- Kernel does not import `@community-hub/db`. Gateway does not import `@community-hub/db`.
- Migration wave is expand only. Recovery is dropping the new table, functions, and trigger.
- The last commit updates `docs/roadmap.md`. Session scratch is never committed.

**Stop and report** (do not work around):

- Built-in `sha256(bytea)` is missing on the Docker 17 image.
- A `Date` round-trip is the only way postgres.js will return the timestamp, and verify then fails the non-zero-microsecond test. Do not change the hash to milliseconds.

`appendAuditEvent` reads `requestId` from `getRequestContext()`. It does not read `idempotencyKey`.

Previous-row assignment inside the trigger (the null arm is the whole genesis path):

```sql
SELECT seq, hash INTO v_prev_seq, v_prev_hash
FROM app.audit_events
WHERE org_id = current_setting('app.org_id')::uuid
ORDER BY seq DESC
LIMIT 1;

NEW.seq := CASE WHEN v_prev_seq IS NULL THEN 1 ELSE v_prev_seq + 1 END;
NEW.prev_hash := CASE
  WHEN v_prev_hash IS NULL THEN decode(repeat('00', 32), 'hex')
  ELSE v_prev_hash
END;
```

`v_prev_seq` and `v_prev_hash` are the only names for those PL/pgSQL variables. Do not name either of them `seq` or `prev_hash`: those are columns of `app.audit_events`, and a later query in the function would raise `variable_conflict`. No row leaves both variables null. Do not wrap the assignment in `IF v_prev_hash IS NOT NULL AND …`.
