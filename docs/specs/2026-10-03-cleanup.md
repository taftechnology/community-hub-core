# Spec: Remove the Workers and broker layout

Slug: cleanup
Status: draft
Architecture refs: §7, §8.1, §8.3, ADR 0009. Implements the cleanup row named in `docs/specs/2026-10-03-personal-data-on-aws.md`. That spec is not edited.

## Problem

`main` still contains the Workers and broker layout that ADR 0009 replaced. `apps/gateway`, the Wrangler files on `apps/api`, the KMS broker, the Cloudflare Terraform, and the checkers for that layout are still built and tested. CI still deploys a Workers preview and still builds the broker image. Until those are gone, the next chunk cannot treat `apps/api` as the Sydney service.

## Scope

**In**

Remove the layout ADR 0009 replaced, and keep the files the service chunk still needs. Staging has never been applied, so this chunk deletes modules from the repo. It does not migrate state and it does not apply.

**Out**

- Reshaping the moved adapter onto `KmsPort`. The service chunk does that. This chunk does not rewrite the SDK calls, the zeroing, or the context allow-list.
- `assertEnvelopeKeyArn`, `server.ts`, `server.test.ts`, and `main.ts`. They are deleted, not moved. The service chunk's spec lists the server tests to port: the 3000 ms default, aborting a call past the deadline, zeroing a result that settles after the deadline, the generic error body, the three log fields, and the ARN check.
- Foundations: tags, budgets, the second public subnet, database changes, the secrets key, the task role, the execution role, and `multi_region = true` on the envelope key.
- Ingress: Route 53, the API certificate, Cloud Map, the VPC link, the HTTP API, and the ECS service module. This chunk does not create a Route 53 zone in place of `infra/global`.
- The first staging apply.
- A privacy-lawyer opinion.

## Behaviour

### What is deleted

- `apps/gateway`, including its Wrangler config, `worker.meta.json`, and tests.
- On `apps/api`: `wrangler.jsonc`, `worker.meta.json`, and the `KMS_BROKER` binding. The app stays.
- `apps/kms-broker` entirely, after the adapter move below: the HTTP server, `server.test.ts`, `main.ts`, the Dockerfile, and the rest of the package.
- `packages/kms-broker` entirely, after the context move below.
- `packages/kms-aws`, including `drift.test.ts`.
- `packages/residency`.
- The checkers `worker-config`, `kms-broker-binding`, `residency-cell`, and `residency-payload`, including their fixtures. `tooling/checks/run.ts` stops calling them.
- Cloudflare Terraform modules: `cf-zone`, `cf-tunnel`, `cf-broker-tunnel`, `cf-vpc-service`, `cf-broker-vpc-service`, `cf-hyperdrive`, `cf-regional-hostname`.
- Broker and tunnel AWS modules: `aws-kms-broker`, `aws-ecs-tunnel`.
- `infra/global`. It only creates a Cloudflare zone. Route 53 waits for the ingress chunk.
- The root `tsconfig.json` references to `packages/kms-broker`, `packages/kms-aws`, `packages/residency`, `apps/gateway`, `tooling/checks/worker-config`, and `tooling/checks/kms-broker-binding`.
- Lockfile entries for the deleted packages. Regenerate the lockfile with pnpm. Do not hand-edit it.

### What moves

Move these files to `apps/api/src/kms/` before deleting their old packages:

- `apps/kms-broker/src/aws-kms-adapter.ts`
- `apps/kms-broker/src/aws-kms-adapter.test.ts`
- `packages/kms-broker/src/context.ts`
- `packages/kms-broker/src/context.test.ts`, with the cut below

`apps/api` gains `@aws-sdk/client-kms` so the adapter tests still run, and `@types/node` because those tests run on Node. The adapter keeps `BrokerKms`'s shape: `(input, { abortSignal })`. It is not reshaped onto `KmsPort`.

### The context tests

`context.test.ts` has two blocks. The `checkContext` block has 12 tests. The `readContract` block has one. Move the first block unchanged. Delete only the second. After the move the file has 12 tests. `ContextRejected` moves with `checkContext`.

The test currently imports `checkContext`, `ContextRejected`, and `readContract` from the built `@community-hub/kms-broker` package. After the move it imports `checkContext` and `ContextRejected` from the local file.

`readContract` has three callers, and this chunk deletes all of them: `apps/kms-broker/src/server.ts`, `apps/kms-broker/src/server.test.ts`, and `packages/kms-aws/src/drift.test.ts`. The contract file `packages/kms-broker/contract/kms-port-v1.json` described the HTTP conversation between the Worker and the broker. That conversation is gone. `context.ts` carries its own allow-list and does not read the contract. Once `context.ts` has moved and `readContract` is deleted, `packages/kms-broker` is empty and is removed.

### `apps/api` tests

The health test uses `cloudflare:test` and the Workers pool, and that pool reads `wrangler.jsonc`. Both go. The test calls the default export's `fetch` with a `Request` on the Node runner. It still proves `GET /health` returns `{ ok: true }` and does not trust an inbound `x-request-id`.

`apps/api` drops `@cloudflare/vitest-pool-workers`, `@cloudflare/workers-types`, and `wrangler`. Its `tsconfig.json` stops listing Workers types. Vitest no longer uses `defineWorkersConfig`.

### Terraform that stays

`aws-network`, `aws-rds`, `aws-kms-storage`, and `aws-kms-envelope` stay. Foundations still owns the envelope key's `multi_region` change, the task role, and the execution role. This chunk does not redesign those modules.

The envelope module takes `broker_tunnel_token` and stores it in Secrets Manager. That token's only source is the deleted broker tunnel. Remove the variable, the secret, the secret version, and the execution-role statement and tests that exist only to read that secret. Leave the key, the interface endpoint, the task role, and the broker security group. The AU root stops passing the token.

In `infra/regions/au`, remove the Cloudflare provider and every module call whose source is a deleted module. Remove the variables and outputs that only fed those modules, including `cloudflare_account_id`, `cert_verification_mode`, `zone_id`, `enable_hyperdrive`, `enable_kms_broker_tasks`, and `kms_broker_image`, and the same keys in the tfvars. Remove the `prod_tls` precondition and check. They exist for Hyperdrive, which ADR 0003 covered and ADR 0009 superseded. Leave the `prod_backup` precondition and check.

`terraform-invariants` stays. It does not mention Cloudflare. Its connector-security-group rule stays, because `aws-network` stays.

### CI

The `broker-image` job is deleted with the Dockerfile.

The Terraform matrix drops `infra/global` and every deleted module. It keeps `infra/bootstrap`, `infra/regions/au`, and the four AWS modules that stay.

Stage 3 builds `@community-hub/api` and does not deploy. It does not run Wrangler, does not upload a version, does not comment a `workers.dev` URL, and does not require a Cloudflare token. The service chunk replaces that build with the ARM image build.

Stage 2 tests `apps/api` on the Node runner.

### ESLint

Delete the `apps/gateway` `no-restricted-imports` block with the app. The db and kernel bans in that block existed for the gateway Worker. They are not copied.

The crypto ban moves to `modules/core/tenancy/**/*.{js,ts}`, including `import type`. That is the platform module in architecture §8.1. Ops routes live on `apps/api`, and this chunk must not ban that app, because the moved adapter calls KMS. There is no ops module directory and no granted-read directory yet. This chunk does not create either. The granted-read exception is added by the chunk that creates that module.

The must-fail fixtures `import-crypto.ts` and `import-type-crypto.ts` move from the gateway fixture path to `modules/core/tenancy` under `tooling/checks/encrypted-column/fixtures/fail/`. The self-test message matches the new rule. The gateway db fixtures go with the gateway block.

- `AGENTS.md` §10 no longer says CI still runs `worker-config`, `kms-broker-binding`, `residency-payload`, `residency-cell`, the Workers test pool, or the Wrangler preview. It describes the Stage 2 and Stage 3 behaviour above.

- `architecture.md` §8.1 no longer says the gateway and the Wrangler files remain on disk until cleanup. The checks line no longer says the edge-runtime checkers leave in cleanup. They have left.
- `docs/roadmap.md`, last commit on the branch: the cleanup row is **done**, last shipped is `cleanup`, next chunk is foundations, and the snapshot counts match the repository-state row.

## Risks

Tenancy. Nothing in this chunk queries the database. The RLS checker stays wired.

Residency. Deleting `packages/residency` and `residency-cell` removes a package nothing in an application imported. Region enforcement stays in the Terraform validations and in `terraform-invariants`. The payload checker goes because a message carrying IDs is a convention, not a checker.

Encryption. The moved adapter still sends `KeyId` on both `Decrypt` and `GenerateDataKey`, still maps the encryption context, still zeroes returned bytes, and still checks the abort signal after send. Those tests move with it. The HTTP broker, which wrapped that adapter, is deleted.

Terraform. Staging has never been applied, so deleting modules does not orphan live state. The envelope module still contains broker-named roles and a broker security group. Foundations replaces those. This chunk does not apply.

CI. A deleted path left in the Terraform matrix, or a Wrangler command left in Stage 3, fails the pull request. The matrix and Stage 3 are part of this chunk.

## Out-of-band

Foundations, ingress, the service, and the first staging apply. No new subprocessor. No lawyer question.
