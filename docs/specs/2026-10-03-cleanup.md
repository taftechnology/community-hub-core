# Spec: Remove the Workers and broker layout

Slug: cleanup
Status: draft
Architecture refs: §7, §8.1, §8.3, §23.3, ADR 0009. Implements the cleanup row named in `docs/specs/2026-10-03-personal-data-on-aws.md`. That spec is not edited.

## Problem

`main` still contains the Workers and broker layout that ADR 0009 replaced. `apps/gateway`, the Wrangler files on `apps/api` and `packages/crypto`, the KMS broker, the Cloudflare Terraform, and the checkers for that layout are still built and tested. CI still deploys a Workers preview and still builds the broker image. Until those are gone, the next chunk cannot treat `apps/api` as the Sydney service.

## Scope

**In**

Remove the layout ADR 0009 replaced, and keep the files the service chunk still needs. Staging has never been applied, so this chunk deletes modules from the repo. It does not migrate state and it does not apply.

This chunk is a deliberate exception to the size guide in AGENTS.md §3. It deletes on the order of 480 files and 8,500 lines. Splitting it would leave a pull request where CI still calls a deleted Wrangler command or a deleted Terraform module. One chunk, because it is one layout.

**Out**

- Reshaping the moved adapter onto `KmsPort`. The service chunk does that. This chunk does not rewrite the SDK calls, the zeroing, or the context allow-list.
- `assertEnvelopeKeyArn`, `server.ts`, `server.test.ts`, and `main.ts`. They are deleted, not moved. The service chunk's spec lists the server tests to port: the 3000 ms default, aborting a call past the deadline, zeroing a result that settles after the deadline, the generic error body, the three log fields, and the ARN check.
- Foundations: tags, budgets, the second public subnet, database changes, the secrets key, the task role, the execution role, and `multi_region = true` on the envelope key. The orphans named under Risks stay until that chunk.
- Ingress: Route 53, the API certificate, Cloud Map, the VPC link, the HTTP API, and the ECS service module. This chunk does not create a Route 53 zone in place of `infra/global`.
- The first staging apply.
- `docs/runbooks/apply-staging-au.md` and the root `.dockerignore`. Both are untouched.
- A privacy-lawyer opinion.
- Calling the Cloudflare API. The account cleanup is a human step under Out-of-band.

- `packages/residency`.
- The checkers `worker-config`, `kms-broker-binding`, `residency-cell`, `residency-payload`, and `bundle-no-zod`, including their fixtures. `bundle-no-zod` is not in `tooling/checks/run.ts`. Its only callers are the two Wrangler dry-run steps this chunk removes from Stage 3. `run.ts` stops calling the four checkers it does import.

### What moves

Move these files to `apps/api/src/kms/` before deleting their old packages:

- `apps/kms-broker/src/aws-kms-adapter.ts`
- `apps/kms-broker/src/aws-kms-adapter.test.ts`
- `packages/kms-broker/src/context.ts`
- `packages/kms-broker/src/context.test.ts`, with the cut below

`aws-kms-adapter.ts` imports `KmsContext` from `@community-hub/kms-broker` and `BrokerKms` from `./server.js`. Both of those homes are deleted. Copy the `BrokerKms` type verbatim from `server.ts` into `apps/api/src/kms/broker-kms.ts`. That file imports `KmsContext` from `./context.js`. The adapter imports `BrokerKms` from `./broker-kms.js` and `KmsContext` from `./context.js`. The type is not rewritten. The adapter keeps `(input, { abortSignal })`. It is not reshaped onto `KmsPort`.

`apps/api` gains `@aws-sdk/client-kms` so the adapter tests still run. The moved adapter already imports it. The package replaces the deleted HTTP broker as the caller of `GenerateDataKey` and `Decrypt`. It is the AWS SDK for JavaScript v3, Apache-2.0. `apps/api` also gains `@types/node`.

### The context tests

`context.test.ts` has two blocks. The `checkContext` block has 12 tests. The `readContract` block has one. Move the first block unchanged. Delete only the second. After the move the file has 12 tests. `ContextRejected` moves with `checkContext`.

The test currently imports `checkContext`, `ContextRejected`, and `readContract` from the built `@community-hub/kms-broker` package. After the move it imports `checkContext` and `ContextRejected` from the local file.

`readContract` has three callers, and this chunk deletes all of them: `apps/kms-broker/src/server.ts`, `apps/kms-broker/src/server.test.ts`, and `packages/kms-aws/src/drift.test.ts`. The contract file `packages/kms-broker/contract/kms-port-v1.json` described the HTTP conversation between the Worker and the broker. That conversation is gone. `context.ts` carries its own allow-list and does not read the contract. Once `context.ts` has moved and `readContract` is deleted, `packages/kms-broker` is empty and is removed.

### `apps/api` tests and types

The health test uses `cloudflare:test` and the Workers pool, and that pool reads `wrangler.jsonc`. Both go. The test calls the default export's `fetch` with a `Request` on the Node runner. It still proves `GET /health` returns `{ ok: true }` and does not trust an inbound `x-request-id`.

`apps/api/tsconfig.json` has `lib: ["ES2022"]` and excludes tests, so `Request` and `AbortSignal` are not in that program. Set `types` to `["node"]` and drop `@cloudflare/workers-types`. Add `tsconfig.test.json`, included from the typecheck script the way `packages/crypto` already does (`tsc --noEmit -p tsconfig.test.json`), so the health test and the moved adapter tests stay typechecked. They were typechecked in their old packages. The move does not drop that.

`apps/api` drops `@cloudflare/vitest-pool-workers`, `@cloudflare/workers-types`, and `wrangler`. Vitest no longer uses `defineWorkersConfig`.

### `packages/crypto`

`packages/crypto` still runs the Workers pool. It has `vitest.worker.config.ts`, `wrangler.jsonc`, `test/workerd-entry.ts`, Workers types in `tsconfig.json` and `tsconfig.test.json`, and a `test` script that runs both Vitest configs. Its Node config already runs the same `src/**/*.test.ts`. This chunk deletes the worker config, the Wrangler file, and `test/workerd-entry.ts`, drops `@cloudflare/vitest-pool-workers`, `@cloudflare/workers-types`, and `wrangler`, and leaves the test script running `vitest.config.ts` only.

`test/tsconfig.json` exists only for `workerd-entry.ts` and for vectors that `tsconfig.test.json` already includes. Delete it. Do not edit it.

Removing Workers types does not compile on its own. With `types: ["node"]` the non-test source still names three Workers types: `CryptoKey`, `SubtleCryptoImportKeyAlgorithm`, and `SubtleCryptoDeriveKeyAlgorithm`. Add `@types/node` and set `types: ["node"]` on `tsconfig.json` and `tsconfig.test.json`. Replace those names with type-only imports from `node:crypto`:

- `CryptoKey` becomes `webcrypto.CryptoKey`.
- `SubtleCryptoDeriveKeyAlgorithm` becomes `webcrypto.HkdfParams`.
- `SubtleCryptoImportKeyAlgorithm` becomes `webcrypto.HmacImportParams` for the HMAC object and `webcrypto.AesDerivedKeyParams` for the AES-GCM object.

Those edits are allowed in `blind-index.ts`, `encrypt.ts`, `hkdf.ts`, `kms-root.ts`, `seal.ts`, `wrap.ts`, `testing.ts`, `blind-index.test.ts`, `encrypt.test.ts`, `kms-root.test.ts`, and `wrap.test.ts`. No other change in those files. There is no runtime change. The existing vectors prove the algorithms. A typecheck of the non-test source is not enough: the typecheck script already runs `tsc --build` and `tsc --noEmit -p tsconfig.test.json`, and both must pass. `testing.ts` is excluded from the build config and is covered only by the test config.

This chunk does not keep `@cloudflare/workers-types` as a types-only dependency. `eslint.config.js` drops the `**/vitest.worker.config.ts` glob from both blocks that list it. After this chunk that glob matches nothing.

### Terraform that stays

`aws-network`, `aws-rds`, `aws-kms-storage`, and `aws-kms-envelope` stay. Foundations still owns the envelope key's `multi_region` change, the task role, and the execution role. This chunk does not redesign those modules.

The envelope module takes `broker_tunnel_token` and stores it in Secrets Manager. That token's only source is the deleted broker tunnel. Remove the variable, the secret, the secret version, the outputs `tunnel_secret_name` and `tunnel_secret_arn`, and the execution-role statement that exists only to read that secret. The mixed assertions are rewritten below, not deleted. All five runs in `infra/modules/aws-kms-envelope/tests/envelope.tftest.hcl` pass `broker_tunnel_token`. Remove that argument from each run. Leave the key, the interface endpoint, the endpoint security group, the task role, the execution role including its `WriteBrokerLogs` statement, the broker log group, and the broker security group. The AU root stops passing the token.

In `infra/regions/au`, remove the Cloudflare provider and every module call whose source is a deleted module. Remove the variables that only fed those modules: `cloudflare_account_id`, `cert_verification_mode`, `zone_id`, `zone_name`, `enable_hyperdrive`, `hyperdrive_origin_password`, `enable_regional_hostnames`, `enable_kms_broker_tasks`, `kms_broker_image`, and `region_key`, and the same keys in the tfvars. Remove the eight outputs that only exist for the deleted modules: `tunnel_id`, `hyperdrive_id`, `vpc_service_id`, `tunnel_token`, `broker_tunnel_id`, `broker_tunnel_token`, `broker_vpc_service_id`, and `connector_execution_policy`.

`region_key` is the Cloudflare regional-hostname key. Its `== "au"` validation and the `wrong_region_key_fails` run go with it. That is not the AWS region check. `aws_region == "ap-southeast-2"` stays on the modules that already have it, and `wrong_region_fails` stays. Region enforcement stays in those validations and in `terraform-invariants`.

Remove the `prod_tls` precondition and check. They exist for Hyperdrive, which ADR 0003 covered and ADR 0009 superseded. Leave the `prod_backup` precondition and check.

`infra/regions/au/tests/cell.tftest.hcl` has a Cloudflare mock provider. Delete that mock. Delete the runs `prod_disabled_tls_fails`, `wrong_region_key_fails`, `broker_flag_off`, and `broker_flag_on`. In `staging_happy` and `prod_tfvars`, delete every assertion that names a deleted module, a Cloudflare resource, `cert_verification_mode`, `region_key`, or a tunnel secret. Keep the assertions about the AWS region, the environment tfvars, backup retention, deletion protection, the storage key, and the envelope key. Keep `wrong_region_fails`.

Two assertions mix a tunnel-secret check with a check that must stay. Rewrite them. Do not delete them.

- `cell.tftest.hcl` in `staging_happy` asserts that `broker_execution_policy` reads the tunnel secret and that no statement action contains `kms:`. `broker_execution_policy` stays. Keep the no-`kms:` half. Drop the half that the policy reads the tunnel secret.
- `envelope.tftest.hcl` in `happy` asserts that the execution policy reads the tunnel secret, writes broker logs, and does not contain `kms:`. Keep the logs half (`logs:PutLogEvents` and the broker log group) and the no-`kms:` half. Drop the half that the policy reads the tunnel secret.

`infra/regions/au/.terraform.lock.hcl` pins the Cloudflare provider. CI runs `terraform init -lockfile=readonly`, so a stale provider entry fails the job. Regenerate that lockfile with Terraform. Do not hand-edit it. Lockfiles inside deleted modules go with those modules.

`terraform-invariants` stays. It does not mention Cloudflare. Its connector-security-group rule stays, because `aws-network` stays.

## Risks

Tenancy. Nothing in this chunk queries the database. The RLS checker stays wired.

Residency. Deleting `packages/residency` and `residency-cell` removes a package nothing in an application imported. Region enforcement stays in the AWS region validations and in `terraform-invariants`. Dropping `region_key` drops the Cloudflare hostname key, not the `ap-southeast-2` check. The payload checker goes because a message carrying IDs is a convention, not a checker.

Encryption. The moved adapter still sends `KeyId` on both `Decrypt` and `GenerateDataKey`, still maps the encryption context, still zeroes returned bytes, and still checks the abort signal after send. Those tests move with it. The HTTP broker, which wrapped that adapter, is deleted. `BrokerKms` moves verbatim so the adapter still typechecks.

Terraform. Staging has never been applied, so deleting modules does not orphan live state. The envelope module still contains the execution role, including `WriteBrokerLogs`, the broker log group, the endpoint security group, the task role, and the broker security group. `aws-network` still contains the connector security group, its Cloudflare egress, and RDS ingress from that connector only. Foundations replaces those. This chunk does not apply.

CI. A deleted path left in the Terraform matrix, a stale Cloudflare provider in the AU lockfile, or a Wrangler command left in Stage 3, fails the pull request. The matrix, the lockfile, and Stage 3 are part of this chunk.

## Out-of-band

Foundations, ingress, the service, and the first staging apply. No new subprocessor. No lawyer question.

CI has run `wrangler versions upload` on pull requests, so a gateway Worker may exist in the Cloudflare account even though Terraform was never applied. A person deletes that Worker, revokes the API token, and removes the repository secrets `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`. This chunk does not do those steps.
