## North star

A current Laravel parish leaves self-hosted Community Hub in **one window**: tenant admin, Parish Hub, and the public website all talk only to core ([architecture §24](../architecture.md#24-migrating-from-self-hosted-laravel)). Client validation uses a **preview hostname in the production account** with real imported data, never staging ([ADR 0018](../docs/adr/0018-client-migration-preview.md)).

**Hard gate before any client moves:** **Two-factor for staff** and **Children's data access** must be shipped. On `staging-au`, donate, form submit, and RSVP succeed on the public site (Jellycube) with synthetic data. Real client data is checked on the production preview hostname only.

`ageOn` throws for a date of birth in the future, which creation refuses, so the list never meets one.

Refusals made before the transaction (400, 401, 402, 403, 404) carry no `no-store` header, all with empty bodies.

An `addedSince` of year 0000 passes the contract and fails in PostgreSQL (rolled back, no data).

The alert after a 409 on the status switch stays until the next action.
